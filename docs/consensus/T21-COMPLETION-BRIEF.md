## What not to do

- No behaviour is documented that the code does not have. When a document promises a control or a flow that does not exist, the promise goes, or it moves to a "not built" sentence with the decision that governs it.
- No document says something ran when it did not. The Docker-backed workflow has not run on a runner. Nothing from this branch has reached the host. The T01 startup-failure file has not executed. The production Bee bridge qualification catalog is empty.
- No em-dashes, no semicolons in prose. Plain sentences. A reader who did not follow the sprint must understand each page on first read.
- No changes to code, tests, workflows or lockfiles. If a document can only be made true by changing code, write down the mismatch in the report instead.

## How to work

- One commit per document, `docs:` prefix, files added by path, nothing under `.scratch/`, no attribution footers.
- For every changed claim, keep a note of the file and line in the code that supports it. Put those notes in the report, grouped by document, so the reviewer can verify each one without re-deriving it.
- Before handing over: `git diff --check`, the prose grep for em-dashes and semicolons across every changed file, and a link check that every relative path in the changed documents exists (`grep -o '(\.\./[^)]*)\|(docs/[^)]*)\|(manager/[^)]*)'` and `test -e` on each).
- Report: the head SHA and commits, each document and what changed in it with the supporting code locations, the stale references found and how each was resolved, the two investigations (STATE.md and CONTEXT.md, the issue records), and any mismatch between documentation and code that needs a code change and was therefore left as a documented gap.
