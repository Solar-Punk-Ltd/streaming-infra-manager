# T20 completion slice: what the reviews found and what changes

Written by Fable on 2026-09-10 after the Opus implementation (branch `feat/t20-ci-completion`, head 722f103, 16 commits over febaf9e) and two parallel reviews on detached worktrees at that head.

## F. Fable's own findings

- **F1 (MEDIUM, the OvenMediaEngine gate fails on a slow package mirror and the failure reads like an engine fault).** `manager/test/docker/ome-admission-gate.sh` starts a publisher container that installs ffmpeg with `apk add` before it publishes, checks that the container is alive five seconds later, and then gives the media playlist forty seconds. On this laptop the install alone took 93 seconds, so the gate failed twice with no engine problem, and passed in 123 seconds once the playlist budget was 180 seconds. Now that the gate is a named job in the manual workflow, a failure that depends on a mirror's speed is a gate that lies. Ruling: the publisher container writes a marker file once ffmpeg is installed and before it publishes, the harness waits for that marker through `docker exec` with its own bounded budget (240 seconds, named as the install budget in the script's header), and only then starts the playlist clock. No new image, no new pin. The harness header records the run on this laptop after the change. `docs/ci.md`'s ome-gate section says the install is waited for and drops the "Levi's call" sentence.
- **F3 (HIGH, a unit test writes a per-deployment env file into the real bundled stack directory).** `manager/test/unit/portTable.test.ts` deploys a profile named `plain` through the orchestrator harness and sets `process.env.SHLS_ROOT` to a temporary root at line 33, but `profileServiceHarness` is imported statically at line 29 and reaches `manager/src/utils/envUtils.ts`, which captures `BUNDLED_STACK_ROOT` at import time. So on every run of the unit suite without `SHLS_ROOT` in the environment, `writeProfileEnv` writes `manager/swarm-hls-stream/.env.plain`, mode 0600, merging whatever `.env` the developer keeps in the submodule. Fable found it by bisecting the suite against a probe root after the correctness reviewer noticed the file in its worktree: on this laptop the file was 3088 bytes, the size of the real stack `.env` plus the generated lines, and it was created at 15:50:57 during the implementer's unit run and again in both review worktrees. The three copies are removed. In CI the `checks` job has no submodule checkout, so the write lands in an empty directory, which is why nothing failed. Fix, in this round because it is the suite the required check runs: the test imports `profileServiceHarness` dynamically after setting the root, exactly as it already does for `orchestratorHarness`, and it asserts after the deploy that `<root>/.env.plain` exists in its own temporary root, an assertion that is red today. Then a guard for the whole suite: a test in `manager/test/unit/` that imports `envUtils` fresh with `SHLS_ROOT` unset and asserts that no other unit file sets `process.env.SHLS_ROOT` after a static import that reaches it, or, simpler and stronger, the manager's `test` script sets `SHLS_ROOT` to a throwaway directory for the whole unit run (`test/unit/run.mjs` or an env in the package script) so a test that forgets can never reach the submodule again, and `docs/ci.md` says so. The implementer chooses the guard and says why. The two review worktrees' `git status --ignored` in the submodule also lists `deploy/config.json` as an ignored file, which is worth a look: if a unit test writes that too, the same guard covers it.
- **F2 (decision for Levi, not a code change).** The checks workflow will cost about 22 Actions minutes per push (estimate 18 to 28), with the browser job more than half. Whether all three jobs stay required on every push, or the browser job moves to a schedule or a manual dispatch, is a spend decision and goes to Levi in the report. Nothing changes in this round.

## C. Correctness review findings (Opus, worktree at 722f103, ten mutations run)

A skipped `describe` registers no test, so the run prints `# tests 0`, `# suites 1`, `# skipped 0` and a `# SKIP` marker on the result line, and the runner printed `PASS: 0 tests, 0 failed, 0 skipped` and exited 0. Pass the TAP body and refuse on any top-level result line carrying `# SKIP`, naming the suite from the line. ## R. What the targeted re-review found

A third review read the fix round in its own worktree at `fe1e2c4`, ran every suite and 24 mutations, and found four things worth changing plus eight small ones. This section says what each became. The work is on the same branch, tests before fixes, one fix per commit.

**HIGH, a second load-sensitive case in the same file, and it failed.** `containerControl.test.ts`, "stops at the total bound when lines keep arriving", writes a line every 10 ms against a 40 ms idle gap and asserts that the 250 ms total bound is what ended the read. One interval tick that fires late leaves a gap wider than 40 ms, the idle bound ends the read first, and the case fails with nothing wrong. It did, in one of the reviewer's six full runs. **Taken.** The idle gap now sits at 5 s and the byte cap at a megabyte, so the total bound is the only exit left, and the case carries a 2 s timeout of its own so that a missing total bound fails in seconds rather than hanging. Turning the total timer off in `readBounded` fails the case in 2003 ms. Four full manager unit runs after the change: 2317 of 2317, no failures, no skips, 21 to 22 seconds each. `docs/ci.md` now names both load-sensitive files under the checks job, says what each used to fail on and how often, and says a red run there is diagnosed rather than retried.

**MEDIUM, the T01 test still printed the secret it was fixed to redact.** node's reporter prints an assertion's own `actual` value, and `assert.equal` appends the whole diff to the error, so matching on the raw rollout reason or comparing the stored engine config published both whatever the message said. The stored config carries the deployment's SRT passphrase and its webhook token. **Taken.** Five assertions in that file now go through `manager/test/support/redactedAssertions.ts`: the reason is matched on its redacted copy, and the config, the template state and the removed profile are compared as answers rather than as values. A unit file drives both helpers with a synthetic config carrying a passphrase and a webhook token and reads back everything the reporter would print. Matching on the raw text turns it red, and so does comparing the value against null.

**MEDIUM, both runners' `main()` was unpinned.** Deleting the suite scan or the preflight from the SQL runner, or making the browser runner discard a skip verdict, left every check green. **Taken.** Each runner is now `run(dependencies)` over its environment, its filesystem, its client and its child process, returning the reasons the run is not green rather than printing them, with an entry point that hands it the real ones. New cases drive both over fakes and record what was asked for: the order, that all nine databases are opened, and that a refusal at any gate ends the run before the next. Removing the scan, the preflight or the judge's verdict now turns those cases red.

**MEDIUM, `pnpm -r test` needed a `manager/.env`.** 26 manager unit files failed at import on a checkout without one, because the config module requires `DATABASE_URL` at load. **Taken.** `manager/test/unit/run.mjs`, which already curates `SHLS_ROOT` for the whole run, now supplies the same placeholder the workflow sets when the environment has none, and a URL the caller exported still wins. The workflow keeps its own placeholder and its comment says it is redundant and kept so the step still states what the run needs. `docs/ci.md` says the same.

**LOW, the gate scan did not match the glob it protects.** **Taken.** It walks the tree now, and takes its directory as a parameter, so a case can build a throwaway directory with a nested suite gated on an unknown variable and watch the refusal name it.

**LOW, the unit runner leaked its throwaway root on a signal.** **Taken.** The run listens for SIGINT and SIGTERM, passes the signal to the child and removes the root there, then stops listening once the child has closed. Checked live: an interrupted run leaves the child gone, no root in the temp directory, and a refusal in words with exit code 1.

**LOW, `FFMPEG_WAIT_SECONDS` counted iterations rather than seconds.** **Taken.** The wait runs until the clock passes a deadline taken when it starts, so 300 means 300 seconds. The gate passed here after the change in 132 seconds, with SRT in, one segment in the media playlist and a signed opening and closing admission call. `PLAYLIST_WAIT_SECONDS` is left counting iterations on purpose: the runs that qualified this gate were measured with it that way, and a 40 that became 40 seconds would be a shorter budget than the one that passed.

**LOW, 63 of 179 browser waits passed no description.** **Taken.** Every one of them now names what it is waiting for, and `waitFor` refuses an absent, empty or blank description before it starts polling. The default budget stays at 15 seconds, for the reasons the re-review gave. Every browser suite ran after the change: 166 of 166 in 364 seconds.

### What stays as it is

- **The shared judge lives in `manager/test/support/`.** Both runners import it and both headers say so, and moving a module across packages to satisfy a reader's expectation needs a home for shared test tooling that this round should not invent on its way past.
- **A browser suite's evidence directory is not removed.** The directories exist so a failed run leaves something to look at, and on a runner `RUNNER_TEMP` is thrown away, so what they cost is temp space on a laptop and nothing on the job.
- **The T02 substring guard still spans the four refused cases.** It guards the fixture strings of a test whose intruder scan already covers all eight, no collision exists today, and widening it changes nothing the harness does.
- **The evidence path scan still matches absolute paths under five roots.** Catching a relative path needs a rule about where a suite may write rather than a wider list of prefixes, and the three suites it was written for now make directories of their own.
- **The two numbers for the browser measurement.** The handover's 351 seconds sits inside a dated block and reads as the history it is, which is how the same question was ruled for the SQL run.

### Two things this round found that the re-review did not

- **The browser flake reproduced, once.** In a run with `T09_TEST_PG_PORT` unset, `pool-draft-browser.test.mjs` failed at its deployment wizard with "Timed out waiting for enabled button Continue", 29 seconds into the case, with a Vite dependency re-optimization in the log beside it. The immediately preceding full run and the immediately following one both passed, 166 of 166 and 163 of 163 with the three connected cases skipped. So it is real, it is rare, and it is now diagnosable from the log alone, which is what the description work was for. Nothing was changed for it in this round: a fix would be a guess until it has been seen more than once.
- **A TypeScript 5.6.3 crash, worth knowing before someone loses an hour to it.** `import assert, { AssertionError } from 'node:assert/strict'` makes `tsc` exit with "Debug Failure" and a stack instead of an error, from anywhere in the project. Splitting it into a default import from `node:assert/strict` and a named import from `node:assert` compiles.
