# The web2 admin link: an uploader linked to the web2 admin out of the box

The web2 admin is a separate service where streams are declared and listed. A
deployment's stream uploader reports to it when the stack gives it
`ADMIN_API_URL` and `ADMIN_API_TOKEN`. Abel found on 2026-09-25 that the manager
gave no way to set this up when creating a deployment, and Levi ruled the same
day that it has to work out of the box on any host a clone of this repository
deploys to, documented for whoever clones it. This page is the design. The
operator's guide, with the routes and what each Test connection outcome means,
is the section [Linking uploaders to the web2
admin](../manager/README.md#linking-uploaders-to-the-web2-admin) of
`manager/README.md`.

Status, 2026-09-26. Built on `feat/admin-link-out-of-the-box`, branched from
`feat/deployment-settings-engine` at `02f699d4`, plan item D of the plan that
makes every stack setting configurable.

## The two keys, and the rule they answer to together

Both keys are typed fields in `common/src/stackSettingFields.ts`, so the page
and the manager hold a value to the same rule before any save. The address is
an http or https address with a host and no user name, password or `#` part,
because the uploader builds every request by adding a path after it. The token
is at least 32 characters, the uploader's own `MIN_ADMIN_API_TOKEN_LENGTH`. No
refusal repeats either value.

The uploader turns admin mode on from the address alone and then refuses to
start without a token. So `adminLinkEditProblem` in `common/src/adminLink.ts`
works out what the two keys come to once a save or a create lands, and refuses
an address with no token anywhere, naming both keys. A token counts wherever it
comes from: stored for the deployment, set by the version, or generated by the
manager for a version that requires it. The manager reads those server side,
where the secrets are, so the check sees an empty token the version sets as
empty. A save that names neither key is not held to the rule, the way a save
that names no engine setting is not held to the engine rules.

## The manager's own link

Migration 041 adds `manager_admin_link`, a single-row table that always holds
its row: the address, or null for no default, the token, a revision a save
names, and who saved it last. The address is answered in clear. The token column
is never selected by a read, only `token IS NOT NULL`, and two things read it:
the insert that copies it into a new deployment, and Test connection. The
columns refuse a token with no address, a token under 32 characters and an empty
address, as a backstop to the service.

It applies to deployments created after it is set. A deployment keeps what it
was created with in its own settings, so a change here reaches no deployment
that exists.

## The copy at insert

A create that asks for the stored token sends `use_manager_admin_token: true`
and never the token. Inside the transaction that inserts the deployment, or each
member of a group, one statement copies the token from `manager_admin_link` into
the new row's `stack_settings_secret` as `ADMIN_API_TOKEN`
(`manager/src/domain/adminLink/adminTokenCopy.ts`). When the manager stores
none by then, the whole insert rolls back, the port slot with it, and the create
is refused with `admin_token_missing`. The token goes from one column to the
other and never through the manager's process or a page.

## Test connection

`manager/src/domain/adminLink/adminLinkProbe.ts` asks what the uploader asks.
First the internal lookup of a stream nobody can have declared,
`GET <address>/api/internal/streams/by-ingest/video/00000000-0000-0000-0000-000000000000`,
with the bearer token. The admin checks the token before anything else, so its
own 404 says it took the token and its own 401 that it did not, each told apart
from any other server's by the error code in its body. Then, where there is a
stream address to compare, the admin's public `GET <address>/api/config`
without the token, for `feed.owner`, compared the way the uploader compares it,
without case and with or without `0x`.

It takes http and https alone, follows no redirect and says so, gives up after
five seconds a request, the uploader's own lookup timeout, and reads at most
64 KiB of an answer. It never throws, and the answer is one outcome code, never
anything the admin said, the address or a token. The log names who tested and
the outcome.

The stream address a deployment's test compares is the `public_key` the manager
holds for its own stream key. A deployment with no stream key of its own signs
with its version's `STREAM_KEY`, whose address the manager does not hold, so its
test compares no owner. The wizard's test compares the address of the stream
key chosen in the step, which the browser derives.

## What it reaches

The test runs from where the manager runs, so an address only the deployment's
own network can reach reads as unreachable, and the page says so beside every
Test connection button. It reaches whatever the manager's host can reach,
loopback and private addresses included, as the uploader reaches whatever its
host can. Every route that tests or edits the link needs a session, and a
signed-in user learns an outcome code and nothing else.

## Where it is set

- **Manager settings**, a page in the navigation with one card:
  `frontend/src/adminLink/ManagerAdminLinkCard.tsx`.
- **The new-deployment wizard's Web2 admin group**, for every goal that runs a
  stream uploader: `frontend/src/forms/wizard/adminLinkChoice.ts` and
  `steps/AdminLinkGroup.tsx`. It follows the manager's link until the operator
  touches it. Switched off, the create stores an empty `ADMIN_API_URL`. Under
  Advanced settings the two keys point at the group, with the owner kind
  `admin-link`, which only the wizard's list uses.
- **A deployment's Stack settings card**, where the two keys are ordinary
  fields, with Test connection right after them:
  `frontend/src/deployments/settings/adminLinkRow.ts`.

`frontend/test/admin-link-browser.test.mjs` drives all three in Chrome at 390
pixels against the mock manager, whose Test connection reads its outcome off the
address, so `https://unreachable.admin.offline.example` answers `unreachable`
and so on, and every sentence can be seen with `pnpm -C frontend dev:mock`.

## Limits

- A create through the API that does not name the admin link gets the version's
  values, not the manager's link. The wizard always names it for a deployment
  that runs an uploader.
- The card's test uses the saved values. A change that is not saved yet is
  tested once it is saved, and the block says so while one is pending.
- A signed-in user can present the manager's stored token to an address typed in
  the wizard, in a test or in a create, so whoever can sign in can send that
  token to a server of their own. The same user can already deploy containers on
  the host.
- A query string in the address passes the field and reaches the uploader, which
  puts its paths after the query and so asks the wrong thing. Test connection
  builds its requests the same way and answers `not-admin` for it.
- The page cannot tell an empty token from a stored one before a save, because
  no secret value reaches it, so the rule on the two keys is answered by the
  manager's refusal under Save rather than before it.
